# PDCA

[English](README.md) · [Français](README.fr.md) · [Español](README.es.md)

PDCA — навык для Claude Code и Codex, который проводит крупные изменения в коде через цикл **Plan → Do → Check → Act** (планирование, реализация, проверка, корректировка). Вы описываете нужный результат, а PDCA разбивает работу на задачи, реализует их отдельными Git-коммитами, проверяет результат по критериям приёмки и при необходимости отправляет изменения на исправление или пересмотр плана.

PDCA подходит для изменений, которым нужны явные зависимости и независимое ревью, например для функции, затрагивающей несколько модулей, миграции или рефакторинга с требованиями к совместимости. Прерванный запуск можно продолжить в новом сеансе. По ходу работы можно посмотреть, что уже сделано и какие решения приняли агенты.

## Требования

- Unix-подобная оболочка и Go 1.22 или новее. Скрипт `scripts/pdca` собирает CLI при первом запуске и пересобирает его при изменении исходников Go.
- Git и целевой репозиторий с хотя бы одним коммитом и чистым рабочим деревом. В Git должны быть настроены имя и адрес автора коммитов.
- CLI Beads (`bd`), доступный через `PATH`. См. [инструкцию по установке Beads](https://github.com/gastownhall/beads/blob/main/docs/getting-started/installation.md).
- Сеанс Claude Code или Codex с поддержкой пользовательских субагентов. Для `pdca once` исполняемый файл `claude` или `codex` должен быть доступен через `PATH`.

## Установка и запуск

### Установите навык

```sh
git clone https://github.com/funkyra/pdca.git
cd pdca
./scripts/pdca install
export PATH="$HOME/.local/bin:$PATH"
```

Установщик создаёт символические ссылки на навык в `~/.claude/skills/pdca` и `~/.agents/skills/pdca` и добавляет ссылку на скрипт в `~/.local/bin/pdca`. Сохраните клон по этому пути, чтобы ссылки работали. Если `~/.local/bin` уже есть в `PATH`, строку `export` можно пропустить. Иначе добавьте её в настройки оболочки, чтобы команда `pdca` была доступна и в новых терминалах.

### Настройте репозиторий, в котором будете работать

Откройте новый сеанс Claude Code или Codex в **целевом репозитории**. Введите соответствующую команду в этом сеансе.

| Действие | Claude Code | Codex |
| --- | --- | --- |
| Настроить репозиторий | `/pdca init` | `$pdca init` |
| Запустить задачу | `/pdca <задача>` | `$pdca <задача>` |
| Продолжить незавершённый запуск | `/pdca resume` | `$pdca resume` |

`init` при необходимости инициализирует Beads, запрашивает модель и уровень рассуждения для каждой фазы, если они ещё не заданы, и создаёт агентов в целевом репозитории: в `.claude/agents/` для Claude Code или в `.codex/agents/` для Codex. Проверьте и закоммитьте файлы настройки, перечисленные в выводе, затем откройте новый сеанс для загрузки агентов. Перед первым запуском рабочее дерево должно быть чистым.

При настройке из терминала можно сразу указать модели. Выполните команду в целевом репозитории. В примере используются имена моделей Claude Code.

```sh
pdca init --harness claude \
  --models 'plan=opus/high do=sonnet/medium check=sonnet/high act=haiku/medium' \
  --review epic
```

### Поставьте задачу

Пример запроса в сеансе Codex.

```text
$pdca Добавь режим пробного запуска для импорта CSV. Выводи количество строк, которые будут добавлены или пропущены, сохраняй данные без изменений и покрой оба режима тестами.
```

Перед работой PDCA проверяет Beads, рабочее дерево, агентов и настройки моделей. С защищённой ветки, например `main`, PDCA переключается на ветку вида `pdca/<краткое-имя-задачи>`. Если вы уже находитесь в ветке для разработки, работа продолжится в ней. Итоговый отчёт содержит имя ветки, число коммитов, задачи на будущее, а также решения и допущения, записанные агентами. Изменения остаются в локальной ветке, где их можно проверить.

### Разовый запуск из терминала

После установки навыка можно запустить отдельный сеанс из целевого репозитория.

```sh
pdca once --harness claude 'Добавь режим пробного запуска для импорта CSV'
pdca once --harness codex 'Добавь режим пробного запуска для импорта CSV'
```

`once` при необходимости инициализирует Beads и открывает выбранный клиент с текстом задачи. Для Claude Code он передаёт агентов в сеанс, а для Codex создаёт их в `.codex/agents/` целевого репозитория. Модели для фаз нужны и при разовом запуске. Дополнительные аргументы клиента указывайте после `--`.

## Как это работает

Основной сеанс запускает нового агента для каждой фазы. CLI на Go проверяет результат фазы и сообщает основному сеансу, какого агента запускать дальше. Инструкции для Plan и Check предполагают использование графа Codebase Memory для изучения целевого проекта.

| Фаза | Что делает |
| --- | --- |
| **Plan** | Превращает запрос в эпик Beads с проектным решением, критериями приёмки и дочерними задачами с зависимостями. Записывает решения и допущения в эпик. |
| **Do** | Реализует и тестирует одну задачу. Каждый успешный раунд реализации или исправления завершается одним коммитом со строкой `Bead: <task-id>` в конце сообщения. |
| **Check** | Проверяет diff, запускает тесты и сверяет результат с критериями приёмки. Записывает вердикт `PASS` или `FAIL` и проверяет, что изменения вместе удовлетворяют критериям эпика. |
| **Act** | Разбирает замечания после `FAIL`. Может закрыть работу, вернуть конкретные исправления в Do, запросить пересмотр плана, завести задачи на будущее или обратиться к пользователю за решением. |

Beads хранит эпик, зависимости задач, ссылки на коммиты, результаты ревью и решения. Изменения кода хранятся в Git. Каталог `.pdca/` содержит локальное состояние, в том числе данные о последней запущенной фазе. Git игнорирует этот каталог. При возобновлении PDCA сверяет это состояние с Beads и Git и определяет, какую фазу запускать дальше.

## Настройка

PDCA читает первый `AGENTS.md`, в котором есть раздел `PDCA models` для выбранного клиента. Поиск идёт от корня репозитория вверх по родительским каталогам, затем по умолчанию проверяется `~/.codex/AGENTS.md`. Команда `pdca init --models` записывает раздел в `AGENTS.md` репозитория. Если подходящего раздела нет, `pdca models --set` позволяет сохранить настройки локально в `.pdca/`.

```markdown
## PDCA models: claude
- plan: opus high
- do: sonnet medium
- check: sonnet high
- act: haiku medium
- review: epic
- parallel: no
```

Для Codex используйте `## PDCA models: codex`, идентификаторы моделей и уровни рассуждения, доступные в вашем сеансе. Четыре строки основных фаз обязательны. Дополнительно можно задать `do_L` и `check_L` для задач размера `L`, `epic_check` и `epic_act` для фаз на уровне эпика и `merge` для интеграции после параллельной группы задач. По умолчанию `merge` использует настройки `check`.

| Параметр | Поведение |
| --- | --- |
| `review: epic` (по умолчанию) | Check проверяет весь эпик после того, как задачи закоммичены. Если ревью не прошло, Act может добавить задачи на исправление. |
| `review: task` | Check проверяет коммит каждой задачи. Вместе с последней задачей проверяется и результат всего эпика. |
| `parallel: no` (по умолчанию) | Do выполняет задачи по одной. |
| `parallel: yes` | Если готовы несколько задач, PDCA запускает до восьми одновременно в отдельных рабочих деревьях Git от одного коммита. Состав группы определяется зависимостями. Перед Check агент Merge переносит коммиты в рабочую ветку, разрешает конфликты и устраняет дублирование кода. |

## Состояние и восстановление запуска

Выполняйте эти команды из целевого репозитория.

| Команда | Что показывает или делает |
| --- | --- |
| `pdca models --harness codex` | Показывает действующие модели, уровни рассуждения, режим ревью и источник настроек Codex. Для Claude Code укажите `claude`. |
| `pdca current` | Находит открытый эпик текущей ветки. |
| `pdca status <epic-id>` | Показывает состояние задач, ссылки на коммиты и вердикты ревью. |
| `pdca brief <epic-or-task-id>` | Показывает сохранённый план или описание задачи, включая критерии приёмки. |
| `pdca report <epic-id>` | Показывает ветку, число коммитов, задачи на будущее и записанные решения. Для корректного числа коммитов запускайте команду в ветке эпика. |
| `pdca next [<epic-id>]` | Проверяет последнюю запущенную фазу и выводит, что делать дальше. Для обычного возобновления в клиенте используйте `/pdca resume` или `$pdca resume`. |

- `FAIL no-beads` означает, что проверка не нашла рабочую область Beads. Убедитесь, что `bd` доступен через `PATH`, затем вызовите `init` в клиенте.
- `FAIL dirty-tree` перечисляет незакоммиченные изменения. Закоммитьте их или временно уберите из рабочего дерева перед повторным запуском.
- `FAIL agents-stale` выводит команду обновления определений агентов. Выполните её и откройте новый сеанс.
- `FAIL no-models` означает, что модели для фаз не заданы. Укажите их в `AGENTS.md` или выполните команду `models --set`, которую вывела проверка.
- `STUCK` сообщает об открытых задачах с незакрытыми зависимостями. `ESCALATE` запрашивает решение, необходимое для продолжения работы.

## Структура репозитория и тесты

| Путь | Содержимое |
| --- | --- |
| [`SKILL.md`](SKILL.md) | Инструкции для основного сеанса, который координирует запуск. |
| [`phases/`](phases/) | Инструкции по настройке, работе агентов и планированию параллельных задач. |
| [`scripts/pdca`](scripts/pdca) | Скрипт сборки и запуска CLI. |
| [`scripts/src/`](scripts/src/) | CLI на Go, проверки фаз, интеграция с Beads и Git, тесты. |
| [`evals/evals.json`](evals/evals.json) | Сценарии проверки навыка и ожидаемые результаты. |

Запустите тесты Go из клона PDCA.

```sh
cd scripts/src
go test ./...
```

Тесты рабочего процесса с Beads пропускаются, если `bd` недоступен.
